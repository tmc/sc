# Experiment O: Trace Prediction

## Goal
Train ML models to predict statechart transitions from ground truth traces generated by Go semantics.

## Approach
- Load JSON traces from `testdata/traces/` (generated by Go trace_generator)
- Train `TracePredictor` model: (current_state, event) -> next_state
- Use cross-entropy loss with label smoothing for stability
- Validate predictions match Go semantics behavior

## Results

### Toggle Statechart (2 states, 1 event)
```
States: [Off, On]
Events: [TOGGLE]
Training samples: 4
Epochs: 500, lr=0.01, embed_dim=16

Final Results:
- Loss: 0.1985
- Training accuracy: 100%
- Evaluation accuracy: 100%

Step-by-step:
  Off + TOGGLE -> pred=On, true=On ✓
  On  + TOGGLE -> pred=Off, true=Off ✓
```

### Hierarchy Statechart (6 states, 3 events)
```
States: [A, A1, A2, B, B1, B2]
Events: [NEXT, PREV, SWITCH]
Training samples: 7
Epochs: 1000, lr=0.005, embed_dim=32

Final Results:
- Loss: 0.9843
- Training accuracy: 42.9%
- Evaluation accuracy: 42.9%

Issues:
- Model predicts composite states (A, B) instead of leaf states (A1, A2, B1, B2)
- Only 7 training samples is very small for 6-state, 3-event space
```

## Key Findings

1. **Toggle works perfectly** - ML successfully learns the alternating TOGGLE behavior
2. **Hierarchy needs improvement** - Composite vs leaf state confusion
3. **Training stability** - Gradient clipping and label smoothing essential
4. **MLX API notes**:
   - No `mx.no_grad()` context manager (remove or use `mx.stop_gradient()`)
   - Use `mlx.utils.tree_map()` for gradient manipulation
   - Use `mx.clip()` for gradient clipping

## Hierarchy Analysis: Why 42.9% Accuracy?

### The Problem
The model confuses composite states (A, B) with leaf states (A1, A2, B1, B2).

### Root Cause Analysis

1. **State Encoding Issue**: Our one-hot encoding treats all states equally, but:
   - A, B are composite states (containers)
   - A1, A2, B1, B2 are leaf states (actual positions)
   - The encoding doesn't capture the hierarchy

2. **Target Ambiguity**: The trace includes composite states in `state_after`:
   ```json
   "state_after": ["__root__", "A", "A2"]
   ```
   We normalize this to a distribution, but the model gets confused about whether
   to predict the parent (A) or child (A2).

3. **Insufficient Data**: Only 7 samples for 6 states and 3 events
   - Toggle had 4 samples for 2 states, 1 event (2 samples per state)
   - Hierarchy has 7 samples for 6 states (1.17 samples per state)

### Predictions Analysis
```
Step | Before | Event  | Pred | True | Issue
-----|--------|--------|------|------|-------
1    | A1     | NEXT   | A    | A2   | Predicted parent, not child
2    | A2     | SWITCH | B1   | B1   | Correct!
3    | B1     | NEXT   | A2   | B2   | Wrong subtree entirely
4    | B2     | SWITCH | A    | A1   | Predicted parent, not child
5    | A1     | PREV   | A1   | A1   | Correct (no-op case)
6    | A1     | NEXT   | A    | A2   | Same as step 1
7    | A2     | NEXT   | A2   | A2   | Correct (no-op case)
```

### Proposed Solutions

1. **Leaf-only encoding**: Filter out composite states from both input and target
   - Only encode leaf states: [A1, A2, B1, B2]
   - 4 states instead of 6, cleaner signal

2. **Hierarchical embedding**: Encode parent-child relationships
   - Add parent indicator: A1 → (A=1, A1=1, A2=0, B=0, ...)
   - Or use learned hierarchical embeddings

3. **More training data**: Generate longer traces
   - Run 20+ steps instead of 7
   - Cover all state-event combinations

4. **Architecture change**: Use DifferentiableTransitionSelector
   - Knows about transition structure
   - Has built-in source/target awareness

## Improvements to Try

1. Filter to leaf-only states in hierarchy traces
2. Increase training data (repeat traces, augment)
3. Use DifferentiableTransitionSelector from exp_c instead of generic MLP
4. Add positional encoding for state hierarchy
